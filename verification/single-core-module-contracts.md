# Single-core module contracts

## Deferred worker dependencies

The one-worker branch of `NuOrderedWorkers::run` returns before any call that uses File::Temp, IO::Handle, POSIX, Storable or Errno. Its callback sequence and error-status reset are unchanged. The multi-worker branch loads those modules before creating its temporary directory or invoking the input callback; calls now name their defining package instead of imported aliases. Under the existing installed-module/API assumptions, these calls resolve to the same functions. Module-load timing and the private imported symbols are intentionally different. This is a source-level argument, not a machine-checked proof of Perl module loading. Tests exercise the serial load set, ordered callbacks, worker failures and cleanup.

## Borrowed columns in mutable record consumers

`fill-an-ac`, `vcf-convert` and `vcf-subset` take a prepared record from their queue, then decode it before any further reader action. The built-in preparer returns a fresh array, or an immutable packed string for workers. The owned-array decoder reads those columns without changing them; mutations later in these commands affect decoded records, not the source array. Passing the existing ownership flag removes the temporary shallow column-array copy. It does not enable genotype sharing in these mutable consumers. The public decoder default still snapshots. The stable-column SMT obligation and limitations in [single-thread-contracts.md](single-thread-contracts.md) apply; arbitrary subclasses/callbacks that mutate the source during decoding are not covered.

## Linear header checking

`vcf-isec` considers only entries with parsed VCF column maps; tabular readers are skipped. Let a header be its column count and complete name-to-position map. Successful pair comparison establishes exact equality of these components. Inductively, all earlier accepted VCF headers equal the first VCF header. Thus checking the next header against the first is sufficient: if it matches, every old pair would match; if it fails, the old loop would fail on that same first VCF before examining another. The original count check, two-direction key checks, key traversal and warning body are retained. Nothing mutates these headers during checking.

`header_equivalence_model.py` checks transitivity for symbolic counts/maps and arbitrary keys. The solver proves the abstract relation; parsed-map construction, finite Perl hashes, their key traversal and diagnostic effects are connected by manual review, not verified compilation. Tests compare the first warning and input immutability with skipped readers, missing/extra/reordered columns and empty headers. The 546-case suite passes with hash seeds 0, 1 and 19; the initial Oscar run used PERL_PERTURB_KEYS=0, and bounded local checks also passed with modes 1 and 2. For F files and C columns, successful checking falls from O(F² C) to O(F C); additional state is one reference index. This is header-validation cost, not an end-to-end speedup claim.

## Bounded raw-byte forwarding and sequence digesting

The vcf-sort chunk-forwarding trial was reverted after measurements showed no material gain. Its tested contract was: after vcf-sort handles headers and its first data line, the remaining stream is forwarded without interpreting records. Concatenating chunks yields the same remaining bytes as concatenating readline results, including an unterminated tail. Sort keys and the external sort command are unchanged. This argument assumes normal Perl byte-stream I/O; it does not establish equivalent partial writes on broken pipes or read errors.

For fill-ref-md5, faidx's first header line is consumed as before. With the CLI's default LF record separator, concatenating every subsequent line after chomp equals removing LF bytes from the remainder of the stream. LF deletion distributes over concatenation, so arbitrary chunk boundaries preserve the sequence and its length. Digest::MD5's incremental add operation consumes those same ordered bytes. CR bytes, NULs and a final unterminated line are retained. The digest library itself is not formally verified here. The temporary buffer is bounded at 64 KiB, in addition to the existing faidx and reheadering processes.

The validator dependency change follows the same control-flow argument as the worker module: normal validation returns before using IPC::Open3 or IO::Select. Unique-message mode requires both before its original fork/selector operations. Installed standard-module behavior is an assumption; only the load timing changes.

`sequence_chunk_model.py` checks the step invariant that the optimized byte feed equals the reference consumed bytes followed by its pending line, and equality after the EOF flush. Initial feeds are empty. Induction covers arbitrary byte sequences and grouping into chunks. This models the bytes supplied to the digest, not the internals of MD5 or Perl I/O.

## Genotype delimiter cursors

The retained `split_gt` implementation keeps the first remaining slash and pipe positions separately. At the start of an iteration, each cursor is either absent or points to the first occurrence of its delimiter at or after the substring start. Selecting the lesser present position therefore emits the same substring as the original two searches. After consuming that delimiter, its cursor is searched again from the new start. The other cursor remains valid: its position is later, or that delimiter was absent in the entire remaining suffix. The initial searches establish the invariant; an absent pair emits the same final substring and terminates. Adjacent and trailing separators consequently retain empty alleles without special cases.

`genotype_cursor_model.py` checks preservation of the unconsumed cursor invariant for arbitrary positions and character arrays. Correct `index`/`substr` semantics, the initial searches, selecting the earlier delimiter and the emitted substrings are connected by manual review. This is not a proof of Perl string internals, tied/overloaded arguments or arbitrary runtime monkey-patching. The differential control compares values and warning bodies for 19,539 inputs, including undefined values, Unicode, embedded NULs, mixed separators and long allele lists.

Each delimiter cursor advances monotonically, so its searched ranges do not overlap. Total delimiter scanning is O(L) in genotype length L, plus output construction. The original repeatedly searches the unconsumed suffix for both delimiters, which can take O(L²) on long strings containing only one delimiter kind. This worst-case bound does not predict an end-to-end gain for ordinary diploid strings. The five real-data caller checks passed; ordinary diploid timings were effectively unchanged. The implementation is retained for its general worst-case bound, without an end-to-end speedup claim for those inputs.
